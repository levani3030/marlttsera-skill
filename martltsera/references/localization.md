## 1. პირველი წესი: პროექტის არსებული ტერმინოლოგია

სანამ ახალ სტრიქონს დაწერ, ნახე, როგორ არის ეს ცნება უკვე ნათარგმნი პროექტში (ლოკალიზაციის ფაილები, გლოსარიუმი, არსებული ინტერფეისი) და იმავე ტერმინს მიჰყევი, თუნდაც §6-ის ცხრილისგან განსხვავდებოდეს. ერთი ცნება — ერთი ტერმინი მთელ პროდუქტში. თუ არსებული ტერმინი აშკარად მცდარია, შეცვლა მომხმარებელს შესთავაზე და თვითნებურად ნუ შეცვლი.

## 2. ლათინური სიტყვა ქართულ ტექსტში

- ბრუნვის ნიშანი და თანდებული ლათინურად დაწერილ სიტყვას **დეფისით** ერთვის: Windows-ის, Google-ში, GitHub-ზე, Android-ისთვის, API-ს, PDF-ად, Copilot-ის. ✗ Windowsის, Windows ის. [MS, AOSP; ენის დეპარტამენტის რეკომენდაცია: Covid-19-ის]
- **სახელობითის -ი ლათინურ სიტყვას არ ერთვის:** ✓ Mail პარამეტრებს იღებს Edge-იდან. ✗ Mail-ი. [MS-სგ]
- მსაზღვრელად მდგომი ბრენდის სახელი ხშირად უნიშნოდ რჩება: Microsoft ანგარიში, Windows ოპერაციული სისტემა; კუთვნილებისას — ნათესაობითი: Windows-ის ინსტალაცია, Office-ის შაბლონები.
- კოდის ფრაგმენტზე: `git commit`-ის შემდეგ; `config.json`-ში; `--force` პარამეტრით.
- ცალკე მდგომი თანდებული ცალკე იწერება: Firefox-ის შესახებ.
- **აკრონიმი + ქართული არსებითი:** პრაქტიკა მერყეობს (PIN-კოდი / PIN კოდი; QR-კოდი; IP მისამართი; IT-განყოფილება). აირჩიე ერთი და პროექტში ბოლომდე მიჰყევი; ახალ ტექსტში რეკომენდებულია დეფისი, როცა ორივე ერთ ცნებას ქმნის (QR-კოდი, PIN-კოდი, USB-კაბელი).
- **ქართულად დაწერილი უცხოური პირველი ნაწილი** — ერთად: ვებგვერდი, ვებსაიტი, ონლაინრეჟიმი, ინტერნეტკავშირი, ელფოსტა, ვიდეოზარი (იხ. compounds.md §3). შენიშვნა: Microsoft-ის ძველ მასალაში დეფისიანი ფორმებიცაა (ინტერნეტ-კავშირი, ვებ-მისამართი); 2025 წლის ნორმით — ერთად.

## 3. ინტერფეისის ტექსტი

- **ღილაკი, მენიუს პუნქტი, ჩანართი — საწყისით (მასდარით):** შენახვა, გახსნა, დახურვა, გაუქმება, წაშლა, ჩასმა, ძიება, გაგზავნა. ✗ შეინახე, შეინახეთ (ღილაკზე). შედგენილი: ფაილის გახსნა, საქაღალდის შექმნა, ანგარიშიდან გასვლა. [MS, Moz, GTK, AOSP]
- **ინსტრუქცია — მრავლობითი ბრძანებითით („თქვენ“):** აირჩიეთ საქაღალდე; დააჭირეთ ღილაკს; შეიყვანეთ პაროლი. მიმართვის ფორმა ერთ პროდუქტში არ აირიოს (შენ / თქვენ).
- **კითხვა:** გსურთ ფაილის წაშლა? / გსურთ, წაშალოთ ფაილი? / ნამდვილად გსურთ გასვლა?
- **მდგომარეობა:** იტვირთება…; ინახება…; შენახულია; დასრულდა; მზადაა.
- **შეცდომის შეტყობინება:** სრული წინადადება ზმნითა და წერტილით — „ფაილი ვერ მოიძებნა.“; „მოხდა უცნობი შეცდომა.“; „პაროლი არასწორია. სცადეთ ხელახლა.“ მოკლე ჭდე/სათაური — ზმნისა და წერტილის გარეშე: „უცნობი შეცდომა“. შეუძლებლობა „ვერ“-ით გამოიხატება: ვერ შეინახა, ვერ დაუკავშირდა (✗ არ შეძლო შენახვა).
- **სიტყვა „გთხოვთ“** მძიმით გამოიყოფა: გთხოვთ, სცადოთ ხელახლა. ყველა შეტყობინებაში ნუ ჩასვამ.
- **ნაცვალსახელი ზედმეტია:** ✗ დაგავიწყდათ თქვენი პაროლი? → ✓ დაგავიწყდათ პაროლი? ✗ თქვენი ფაილი აიტვირთა → ✓ ფაილი აიტვირთა.
- ინტერფეისის ელემენტის სახელი ტექსტში ბრჭყალებში: დააჭირეთ ღილაკს „შენახვა“; გახსენით „პარამეტრები“.
- შეყვანის ყველა მეთოდისთვის გამოსადეგი ზმნა: აირჩიეთ (და არა მხოლოდ „დააწკაპუნეთ“ / „შეეხეთ“), თუ პლატფორმა ერთი არ არის.
- სათაურსა და ჭდეს ბოლოში წერტილი არ აქვს; ორწერტილი ველის ჭდის შემდეგ — პროექტის წესით.
- ქართული ტექსტი ინგლისურზე ხშირად გრძელია; ვიწრო ელემენტში სიტყვას ნუ შეამოკლებ თვითნებურად — შეცვალე ფორმულირება.

## 4. ცვლადები და ჩასასმელი ადგილები

ქართული ბრუნვის ნიშანი სიტყვას ერთვის, ამიტომ ცვლადიანი სტრიქონი ყურადღებას ითხოვს.

- ცვლადს ნიშანი დეფისით ერთვის: `%s-ის ჩანაცვლება`, `{name}-ს გაეგზავნა`, `{count} ფაილი`. [MS-სგ]
- დეფისიანი ნიშანი ყველა მნიშვნელობას ვერ მოერგება (ქართული სახელი დეფისს არ საჭიროებს, ფუძე შეიძლება იკუმშებოდეს). **უსაფრთხო გზა — ცვლადი სახელობითში დატოვო** და წინადადება ისე ააგო, რომ ბრუნება არ დასჭირდეს:
  - ✗ `{user}-მა წაშალა ფაილი` → ✓ `ფაილი წაშალა მომხმარებელმა: {user}`
  - ✗ `{file}-ის წაშლა` → ✓ `ფაილის წაშლა: {file}` ან `წაიშალოს ფაილი „{file}“?`
  - ✗ `დაკავშირება {device}` → ✓ `{device}: დაკავშირება` ან `მოწყობილობასთან დაკავშირება: {device}`
- **რიცხვი + არსებითი:** რიცხვის შემდეგ არსებითი ყოველთვის მხოლობითშია, ამიტომ ქართულს ცალკე plural-ფორმა არ სჭირდება: `{count} ფაილი` (1 ფაილი, 5 ფაილი). ICU/gettext plural-ში ერთი ფორმაც საკმარისია (ან one და other ერთნაირი). ✗ `{count} ფაილები`.
- რიცხვიან ცვლადთან თანდებული: `{n}-იდან {m}-ამდე` მხოლოდ მაშინ, თუ ყველა მნიშვნელობაზე სწორია (8-მდე, 9-მდე გამონაკლისია); უსაფრთხოა `{n}–{m}`.
- წინადადების ნაწილებად დაჭრილი სტრიქონები (concatenation) ქართულში თითქმის ყოველთვის ტყდება; ითხოვე სრული წინადადება ერთ სტრიქონად.
- ცვლადის სახელს, ფორმატის მაჩვენებელს (`%s`, `%1$d`, `{0}`), HTML-ტეგს, escape-მიმდევრობას არ ცვლი; ბრჭყალებს კოდის სინტაქსში არ ცვლი ქართულით.

## 5. რა არ ითარგმნება

- პროდუქტის, ბრენდისა და კომპანიის სახელები: Microsoft 365, OneDrive, Wi-Fi, Bluetooth, GitHub, .NET Framework.
- აკრონიმები: API, URL, HTML, CSS, JSON, SQL, PDF, USB, PIN, GPS, LLM, AI (ტექსტში შეიძლება გაშლა: ხელოვნური ინტელექტი (AI)).
- კოდის იდენტიფიკატორები, ბრძანებები, ფაილის სახელები და გზები, გაფართოებები, კლავიშების სახელები (Ctrl, Enter, Tab, Esc), ვერსიის ნომრები (ვერსია 4.2 — წერტილით).
- ლოგის შეტყობინებები, შეცდომის კოდები, API-ს ველების სახელები.
- ახალი აკრონიმის გამოგონება ქართული თარგმანიდან არ შეიძლება (✗ „ხი“ AI-ს ნაცვლად).

## 8. კოდი, commit-ები, კომენტარები

- კოდის კომენტარი და commit-შეტყობინება ქართულად მხოლოდ მაშინ დაწერე, თუ პროექტში ასეა მიღებული ან მომხმარებელი ითხოვს; იდენტიფიკატორები ყოველთვის ლათინურია.
- ქართულ სტრიქონში კოდის სინტაქსის ბრჭყალი უცვლელია; ტექსტის შიგნით — ქართული ბრჭყალი: `t("გსურთ, წაშალოთ „{name}“?")`.
- JSON/YAML/properties ფაილებში ქართული ტექსტი UTF-8-ით ინახება; `\uXXXX` escape-ებად ნუ გადაიყვან, თუ ფორმატი არ ითხოვს.
- სტრიქონის სიგრძე: ქართული ასო UTF-8-ში 3 ბაიტია; ბაიტებით შეზღუდულ ველებში გაითვალისწინე.
- ტექსტის ძებნა/დალაგება: ქართულს რეგისტრი არ აქვს; `toUpperCase()` მთავრულ ასოებს იძლევა (იხ. numbers.md §8).

## 9. ტონი

ბუნებრივი, მოკლე, საქმიანი; ოფიციალური კანცელარიული სიტყვების გარეშე (იხ. style.md). მარტივი სიტყვა სჯობს რთულს: „მეტია“ („აღემატება“-ს ნაცვლად), „ასევე“ („დამატებით“-ის ნაცვლად). ეს არჩევანია ახალი ტექსტის წერისას და არა შეცდომა სხვის ტექსტში. მომხმარებელს ნუ დაადანაშაულებ: „პაროლი არასწორია“ და არა „თქვენ შეიყვანეთ არასწორი პაროლი“.
